2.1 知识库构建模块：从“能用”到“好用”的基石
摘要中提到了“解析、分词与语义切分”，这涵盖了知识库构建的核心流程。但要构建一

2.1.1 文档解析与预处理
挑战： 高校规章制度通常是包含复杂格式的 PDF 文档，其中混杂着表格、列表、图表、
页眉页脚等。直接提取纯文本会丢失大量结构化信息，甚至破坏语义。例如，一个关于奖
学金评定标准的表格，如果被粗暴地转为纯文本，其行列关系将不复存在，LLM 难以正确
理解。
深度实现建议：
采用先进的文档解析工具： 不应满足于简单的 PyPDF2 等库。应研究并使用如
unstructured.io、LlamaParse 或结合 OCR 技术的方案（如 PaddleOCR），这些工具能更好地
解析 PDF 中的表格、列表等结构，并将其转换为 Markdown 或 JSON 等半结构化格式。
处理表格数据： 对于解析出的表格，不应将其简单地线性化为文本。可以尝试将其转换
为 CSV 格式或直接在 Prompt 中以 Markdown 表格形式提供给 LLM，以最大限度地保留其
结构信息。有研究表明，这能显著提升 LLM 对表格内容的理解能力 [[31]]。
元数据（Metadata）提取与利用： 在解析文档时，应尽可能提取元数据，如文件名、发
布日期、发布部门、制度的生效/失效日期、版本号等。这些元数据在后续的检索过滤和版
本控制中至关重要。
2.1.2 文本切分（Chunking）策略
摘要中提到的“语义切分”是关键。这是决定 RAG 系统召回质量的“咽喉”环节。
传统方法的局限： 简单的固定长度切分（Fixed-size Chunking）或递归字符切分
（Recursive Character Text Splitting）虽然实现简单，但极易在语义单元的中间断开，导致
上下文信息不完整 [[32]][[33]]。
“语义切分”的深化实现：
基于规则的结构化切分： 利用文档的章节（如“第一章”、“1.1 节”）、段落、标题
等自然结构进行切分。这要求预处理阶段能准确识别这些结构。
内容为 AI 生成，可能不准确，请谨慎参考
基于 NLP 的句子切分： 使用 spaCy 或 NLTK 等库，将文档先切分为句子，再将语义相
近的连续句子组合成一个 Chunk。
基于嵌入模型的语义切分（Semantic Chunking）： 这是一种更先进的方法。它计算连
续句子（或小段落）之间嵌入向量的余弦相似度。当相似度出现一个“断崖式”下降时，
就认为这里是一个语义边界，适合进行切分 [[34]][[35]]。这种方法能最大程度地保证每个
Chunk 内部的语义连贯性。
Agentic Chunking： 2025-2026 年兴起的一种更智能的思路，利用一个强大的 LLM（如
GPT-4）作为“切分智能体”，让它阅读一小段文本后，自己判断在哪里切分最合理。虽
然成本较高，但在处理复杂、无明显结构化特征的文本时效果优异。
最佳实践建议： 毕业设计中可以实现并对比多种切分策略，例如，实现一个基础的递归
字符切分作为 Baseline，然后重点实现并优化一种语义切分策略，通过实验数据证明其优
越性。

2.2 混合检索模块：确保“找得准、找得全”
摘要中的“混合检索”是提升召回率和精确率的关键。
为何需要混合检索：
向量检索（语义检索）： 擅长理解“同义不同词”的模糊查询。例如，用户问“没钱交
学费怎么办”，它可以召回到关于“助学贷款”、“困难补助”、“绿色通道”的相关条
例。
关键词检索（如 BM25/TF-IDF）： 在处理包含特定术语、编号、人名等专有名称的查
询时表现更佳。例如，用户问“《XXX 大学本科生学籍管理规定》的第十五条是什么”，
关键词检索能精准定位。
实现策略：
1.并行检索与融合： 分别执行向量检索和关键词检索，然后对两路结果进行融合。融合策
略是研究的重点，简单的方法是加权组合分数，但更高级的方法是使用重排序模型（Re-
ranking Model）。

2.重排序（Re-ranking）： 将两路召回的前 K 个结果（例如，总共 20 个文档块）合并，然
后使用一个更强大的 Cross-Encoder 模型对“查询”和每个“文档块”的对（pair）进行打
分，根据这个更精确的相关性分数重新排序，最后选择 Top-N（例如，Top 3-5）个文档块
作为最终上下文。这在 2026 年已被证明是提升 RAG 性能的 SOTA（State-of-the-Art）方法
之一。
3.深化建议： 论文中不仅要实现混合检索，更要花篇幅研究和实验不同的融合策略和重排
序模型，并用评测数据（如 MRR, NDCG@k）来量化不同策略带来的提升 [[46]][[47]]。
2.3 智能生成模块：确保“说得对、说得好”
这是 RAG 的最后一环，也是直接面向用户的一环。
Prompt Engineering 的艺术： 约束 LLM 基于本地知识生成回答的核心在于精心设计的
Prompt。一个好的 Prompt 模板通常包含：
角色设定： "你是一个精通 XX 大学所有规章制度的智能助手，你的回答必须严谨、准确、
并基于我提供的上下文。"
上下文注入： Context: {retrieved_chunks}
任务指令： "请根据以上上下文，回答用户的问题。如果上下文中没有足够信息，请明
确告知用户'根据现有资料无法回答该问题'，严禁自行编造。"
用户问题： Question: {user_query}
格式要求： "请用清晰、分点的形式回答。如果可能，请在回答的每一部分后面注明信
息来源的文档名称和章节。"
处理多轮对话上下文：
挑战： 用户的问题常常是连续的，例如：“申请奖学金需要什么条件？” -> “那对英语
四级有要求吗？”。系统需要理解第二问中的“那”指的是“奖学金申请”。

实现方法：
1.对话历史管理： 将最近的几轮对话历史一并加入到 Prompt 中。
2.查询重写（Query Rewriting）： 在进行检索之前，先用一个 LLM 将会话历史和当前问
题作为输入，生成一个独立的、包含完整上下文的新查询。例如，将 {"history": "Q:申请奖
学金需要什么条件? A:...", "current_q": "那对英语四级有要求吗？"} 重写为 "申请奖学金对
英语四级有要求吗？"。然后再用这个重写后的查询去进行检索。这是 2026 年处理 RAG 多
轮对话的主流且高效的方法 [[48]][[49]]。
生成溯源（Citation）： 这是提升系统可信度的关键功能。系统不仅要给出答案，还要
能告诉用户答案是基于哪份文件的哪个部分。实现上，可以在检索到的文档块中包含其元
数据（文件名、页码、章节号），并在 LLM 生成答案后，通过后处理步骤，将答案内容与
来源块进行匹配，从而附上引用。

1. 动态知识更新机制： 这是摘要中一个非常亮眼的提法，也是一个重要的创新点。传统知

4. 结构化知识与非结构化知识的融合（GraphRAG）：
*   这是一个极具前瞻性的创新方向。除了向量数据库中的非结构化文本块，还可以构建一

1. 检索模块评测（Component-level: Retrieval）：

度和其在结果中的位置，是衡量排序质量的黄金指标 [[65]][[66]]。

*   Faithfulness (忠实度): 生成的答案是否完全基于提供的上下文，没有添加外部信息或产
